# S1 스터디룸 예약 — 스펙 (Ready)

## 스토리

회원으로서, 날짜와 시간을 골라 스터디룸을 예약해서 팀 스터디 장소를 확보하고 싶다.

## AI 질문과 팀의 답

`docs/templates/01-ai-question-prompt.md`로 AI에게 받은 질문과 팀이 정한 답입니다.

| AI의 질문 | 팀의 답 |
| --- | --- |
| 시간은 어떤 단위로 받나요? 시간대는? | 30분 단위, 한국 시간(KST) 고정 — ADR-001 |
| 겹침의 기준은? 16:00에 끝나고 16:00에 시작하면? | 시작 포함·종료 미포함 구간. 맞닿는 것은 허용 |
| 운영 시간과 최대 이용 시간은? | 09:00–22:00, 한 번에 최대 4시간 |
| 지난 시간 예약은? | 거절 (시작 시각이 지금보다 미래여야 함) |
| 누가 예약하는지 어떻게 아나요? | 실습에서는 `X-Member-Id` 헤더 — ADR-002 |
| 실패 응답 형식은? | `{ code, message }`, 상태 코드는 아래 표 |

## 인수조건

```gherkin
시나리오: 정상 예약
  Given 2026-10-20 A룸에 예약이 없을 때
  When  회원 minsu가 14:00–16:00으로 예약하면
  Then  201과 함께 status가 CONFIRMED인 예약을 받는다

시나리오: 겹치는 예약
  Given A룸 14:00–16:00 예약이 있을 때
  When  15:00–17:00으로 예약하면
  Then  409 RESERVATION_CONFLICT

시나리오: 맞닿는 예약
  Given A룸 14:00–16:00 예약이 있을 때
  When  16:00–18:00으로 예약하면
  Then  201 (겹침이 아니다)

시나리오: 다른 룸은 같은 시간도 가능
  Given A룸 14:00–16:00 예약이 있을 때
  When  B룸 14:00–16:00으로 예약하면
  Then  201

시나리오: 잘못된 시간
  When  종료가 시작보다 빠르거나, 30분 단위가 아니거나, 09:00–22:00 밖이거나, 4시간을 넘거나, 이미 지난 시각이면
  Then  400 VALIDATION_ERROR

시나리오: 없는 룸
  When  Z룸을 예약하면
  Then  404 ROOM_NOT_FOUND

시나리오: 로그인하지 않음
  When  X-Member-Id 없이 예약하면
  Then  401 UNAUTHORIZED
```

## 제약 · 금지

- 계약: `docs/api-spec.yaml`의 `POST /api/reservations`
- 결정: ADR-001(시간), ADR-002(인증), ADR-003(저장소)
- 금지: 요청 본문으로 회원 ID 받기, 현재 시각을 `new Date()`로 직접 읽기
