# Before vs After — DoD로 채점하기

같은 백로그(S1~S3)를 두 방식으로 만들었습니다.

- **before**: "스터디룸 예약 서비스 만들어줘" 한 줄. 규칙도 스펙도 주지 않음.
- **after**: AI 질문 → 팀의 답 → 인수조건(docs/specs) → ADR → AGENTS.md → 테스트 먼저 → 구현.

## 1. 같은 시나리오, 다른 결과

두 서버에 같은 요청을 실제로 보내 본 결과입니다. (A룸 14:00–16:00 예약이 이미 있는 상태)

| # | 시나리오 | 기대 | before | after |
| --- | --- | --- | --- | --- |
| 1 | 15:00–17:00 겹치는 예약 | 거절 | **200 예약됨** (시작 시각이 같을 때만 검사) | 409 RESERVATION_CONFLICT |
| 2 | 16:00–18:00 맞닿는 예약 | 허용 | 200 | 201 |
| 3 | 없는 예약 번호 999 취소 | 404, 다른 예약 영향 없음 | **200 "취소 성공" + 남의 마지막 예약이 삭제됨** | 404 RESERVATION_NOT_FOUND |
| 4 | 남의 예약 취소 | 거절 | **200 취소됨** (본인 확인 없음) | 403 FORBIDDEN |
| 5 | 시작 30분 전 취소 | 거절 (1시간 전까지) | **200 취소됨** (마감 규칙 없음) | 422 CANCEL_DEADLINE_PASSED |
| 6 | 없는 룸 Z 예약 | 거절 | **200 예약됨** | 404 ROOM_NOT_FOUND |
| 7 | 종료가 시작보다 빠른 예약 | 거절 | **200 예약됨** | 400 VALIDATION_ERROR |
| 8 | 관리자 조회 | 관리자만 | 쿼리 `?password=admin1234` (코드에 비밀번호) | `X-Role: admin`, 아니면 403 |

3번이 가장 위험합니다. `findIndex`가 못 찾으면 `-1`을 돌려주고, `splice(-1, 1)`은 **배열의 마지막 예약**을 지웁니다. 데모에서는 절대 보이지 않는 버그입니다.

## 2. DoD 채점

| DoD 항목 | before | after |
| --- | --- | --- |
| 인수조건의 모든 시나리오가 자동 테스트로 통과 | ❌ 인수조건 없음, 테스트는 서버 기동 확인 2개뿐 | ✅ 29개 테스트 통과 |
| 작성자가 코드를 설명할 수 있다 | ❌ "왜 시작 시각만 비교했나?"에 답할 근거 없음 | ✅ 모든 규칙이 스펙·ADR에 근거 |
| 리뷰어 1명 승인 | ❌ 리뷰할 기준(스펙)이 없음 | ✅ 스펙 대비 리뷰 가능 |
| 비밀키 하드코딩 없음 (`npm run check:secrets`) | ❌ `ADMIN_PASSWORD = "admin1234"` | ✅ 통과 |

**결과: before는 '동작함', after는 '완료됨'.** 데모만 보면 둘 다 잘 돌아갑니다.

## 3. 코드에서 보이는 차이

| 관점 | before | after | 근거 |
| --- | --- | --- | --- |
| API 경로 | `/reservations`, `/my-reservations`, `/admin/reservations` 제각각 | `/api/...`로 통일 | api-spec.yaml |
| 필드 이름 | `room`, `userId`, `user_id` 섞임 | `roomId`, `memberId` (camelCase) | AGENTS.md |
| 회원 식별 | 요청 본문의 `userId` (누구나 남을 사칭 가능) | `X-Member-Id` 헤더 | ADR-002 |
| 현재 시각 | `new Date()` 직접 호출 → 시간 규칙을 테스트할 수 없음 | `now()` 주입 | ADR-001 |
| 상태 | 모듈 전역 배열 → 테스트끼리 데이터가 섞임 | `createApp()`마다 새 저장소 | ADR-003 |
| 취소 | 데이터 삭제 | `status: CANCELLED` | ADR-003 |
| 성공 코드 | 생성도 200 | 생성 201, 취소 204 | api-spec.yaml |
| 에러 메시지 | 영어, 형식 제각각 | `{ code, message }` 한국어 | AGENTS.md |

## 4. 무엇이 차이를 만들었나

AI의 실력 차이가 아닙니다. 두 버전 모두 같은 수준의 AI가 만들 수 있는 코드입니다.
차이는 **AI에게 무엇을 줬는가**에서 나왔습니다.

| after에서 AI에게 준 것 | 막아 준 문제 |
| --- | --- |
| 인수조건 "15:00–17:00은 409, 16:00–18:00은 201" | 1, 2번 (겹침 기준) |
| 인수조건 "없는 예약 → 404, 다른 예약은 그대로" | 3번 (splice 버그) |
| 인수조건 "남의 예약 → 403", "13:30 → 422" | 4, 5번 |
| ADR-001 (시간 규칙), 테스트 먼저 | 7번, 시간 테스트 가능성 |
| ADR-002 + AGENTS.md 금지 항목 + CI 시크릿 검사 | 8번 |

## 강의에서 쓰는 법 (수업 7-5)

1. 수강생이 자기 실습 A 결과로 표 1의 시나리오 1, 3, 5를 먼저 직접 시도해 보게 합니다.
2. 그다음 이 문서의 표 1을 보여 줍니다. "내 코드도 3번 버그가 있었다"는 수강생이 꼭 나옵니다.
3. 표 4로 마무리합니다. **"AI를 바꾼 게 아니라, AI에게 준 것을 바꿨다."**
